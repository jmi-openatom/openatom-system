# /about 视觉与交互重设计规格

日期：2026-09-04。范围仅为 `frontend/web_pc/src/views/site/About.vue` 对应的 `/about`，不涉及首页、管理后台或报名业务的重写。本次交付为设计与开发规格，尚未实现新版。

## 1. 设计结论

方向：**校园里的开放实验室 / OPEN LAB**。

不是再做一份部门招新长海报，而是讲清楚：一群校园创作者为什么聚在一起，怎样协作，做出了什么，以及新成员如何参与。

三个主记忆点：真实校园与创作者的开场、把一个问题共同做成作品的短篇滚动故事、由真实产品界面主导的项目展台。结尾用开场文案的回应收束，不另加第四套视觉语言。

保留原有社团名称、徽标、学校归属和“开源筑梦，海事启航”；不修改官方标志造型或配色。Apple 风格原则用于空间、文字与层级，不照搬其产品页模板；UI/UX 与 GSAP 规范用于自主导航、减少动态效果和动画生命周期。

## 2. 当前页面审视

依据：当前工作区源码与本次本地浏览器截图。桌面检查尺寸 1440×1000；检查了移动端重排，但未完成移动端完整流程、读屏、200% 缩放与性能测试。不把本地数据视为已核验的公开成果。

### 01 首屏：影像真实，价值表达不足

优点：校园照片、社团身份、大字号标题已经成立。问题：满屏影集在视觉上更接近校园宣传页；名称与口号之外，缺少“在这里能做什么”的直接表达和作品入口。九张图片每五秒自动切换，没有独立暂停按钮。现有首张图片约 1.1 MiB，其他图片也较大；这是磁盘文件大小，不是首屏实际下载测量。

![现状 01：桌面首屏](/Users/ariven/1-jmiopenatom/openatom-system/docs/design/about-redesign-2026-09-04/about-01-hero.png)

### 02 理念与路线：内容有价值，篇幅和交互权重失衡

创立年份与“先做出来，再一起做得更好”值得保留。现状理念仍是两张大卡片；大量区域共用整屏最小高度。源码中的五条路线固定区还增加 `innerHeight * 5` 的滚动距离，且普通移动模式也执行 pin 和 snap。桌面当前项目区起点约在 8000px，即约八个视口之后。路线导航为静态列表，不能直接选择章节。

### 03 项目：最需要重构的区域

现有大面积协作插画很有氛围，但三张等宽文字卡没有产品截图、访问入口与成果证据。当前页面出现“跑出趣 (Run & Fun)”搭配“AI 实验”默认说明：`featuredProjects` 按数组 index 将接口项目与 fallback 项目混合，名称和成果说明可能不属于同一项目；部门路线也存在按 index 覆盖标题、保留原任务文案的风险。

现有“下一段开源故事，等你来写”与报名 CTA 已经成立，并非缺少结尾。需要让它与首屏构成呼应，把报名流程和 FAQ 变成最终行动前的减压信息，而不是连续多个同权重整屏。

## 3. 完整叙事与布局

顺序：品牌身份 → 存在理由与协作方法 → 真实作品 → 成果证据与同行者 → 我的参与方向 → 入社后的成长 → 未来愿景 → 报名流程、FAQ 与最终 CTA。

### 01 BrandHero：一起，把想法做出来。

- 固定品牌标识为“开放原子开源社团 / JMI-OPENATOM”，主标题建议“把想法，做出来。”，辅文“在江苏海事，从真实问题出发，和伙伴一起设计、开发、分享。”旧口号保留为署名。
- 桌面 12 栏：左侧约 7 栏为文字，右侧约 5 栏为真实协作照片或经过脱敏的项目界面近景。文字可跨入图片留白，不压住人物面部。主画面不使用全屏自动影集。
- 右侧主图边缘可叠一张小幅实际产品截图，最多两个视觉层；不要伪造代码、使用人数、贡献状态。
- 主 CTA“看看我们做了什么”跳转项目，次入口“找到我的方向”跳转路线；页头保留返回官网，并增加故事、作品、参与三个锚点和“了解招新”。
- 初始文字完整可读，不能等动画结束才出现；装饰影像 600–800ms 内完成一次轻微入场。标题不无限轮换，避免身份信息消失。
- 首次向下滚动，主图缩放 1.03 → 1，带入理念段；不 pin 首屏。
- 移动端文字在上、裁切后的真实影像在下，标题 44–52px，两行以内为目标；入口至少 44px 高，不固定一屏高度来裁切内容。
- 现有九张照片全部保留在后面的社区影集入口中，默认手动浏览。

### 02 OriginStory：好奇心，需要一个共同动手的地方。

- 合并原 story 的创立年份与理念，取消两张等高卡片。左上“始于 2025”是时间注脚，主角是原文“先做出来，再一起做得更好”。年份与事实发布前复核。
- 用三段短文讲方法：看见问题 → 接住任务 → 分享成果。每段对应真实素材，例如需求记录、任务讨论、公开成果；没有素材时保留清晰文字，不做假聊天记录。
- 桌面左侧图像可 CSS sticky，右侧三段内容自然流过，总长度约 140–180svh；右侧句子一开始就可读，只改变强调与对应图片，不逐字遮挡整段正文。
- 过渡句：“这些协作，已经变成了可以打开的作品。”直接引出项目。
- 移动端改三段自然文流，取消 sticky 与视差。

### 03 ProjectShowcase：不是概念。可以打开。

- 成为全页视觉高潮，顺序提前到第三章。全宽石墨背景，产品截图保留原色；不在项目正文下面铺高对比人物插画。
- 桌面两栏：约 38% 为连续的项目说明，62% 为 sticky 产品画面；每个项目说明进入视口时切换对应截图。使用自然文档滚动，避免 pin 整页或强制 snap。
- 第一项目使用现有 openatom-system：主画面选择可公开、已脱敏的真实功能界面。第二候选为 openatom-website-publish；第三项目按内容完整度选择，不能为了凑三项把 Run & Fun 填成 AI 项目。
- 每个项目固定内容结构：服务谁、解决什么、做到了什么、谁参与、如何验证。最多三项真实成果，不写未核验的增长百分比或规模数字。
- 显式提供“查看项目”，映射既有 `/apps/:id`；有核验仓库地址才提供“查看源码”，有可用演示才提供“体验演示”。这些链接是独立语义链接，不把整张卡片套成嵌套链接。
- 产品界面通常 `object-fit: contain`；展示完整流程而非裁掉关键界面。截图预留 aspect-ratio，切换时不让文字跳动。
- 首项目一幅大图，后续项目用不同构图体现产品类型；移动端按项目逐个展示“图片 + 说明 + 链接”，三项内容都可见，无横向强制滚动。
- 只有一个合格项目时做单项目大展示；没有合格项目时展示真实可用的应用目录入口，不伪造作品墙。

### 04 EvidenceCommunity：作品背后，是一起做事的人。

- 连接原 awards 与 community。荣誉用紧凑时间线/编辑式列表，不再独占统一整屏；保留赛事、年份、等级与团队信息，支持展开详情。
- 下方用真实活动照片和成员故事构成不对称版面：大图约 7 栏、成员原话约 5 栏。现有匿名引语须核验来源并取得公开授权；不能核验时改成不带引号的社区原则，不伪装成见证。
- 原黑白社区插画可作为影集空态或次要视觉，不同时充当两个大区域的通用背景。
- 可展示至多三个已核验统计，必须写清统计口径与截至时间；没有稳定数据就用荣誉与作品本身，不新增无来源“活跃度地图”。
- 九张原照片放入可手动翻页的影集，显示有意义的照片说明；若提供自动播放，必须有暂停、焦点进入暂停、离屏暂停和减少动态效果支持。
- 过渡句：“你不必和我们一样，才能一起做事。”

### 05 ParticipationPaths：五条路线，不止一种参与方式。

- 保留项目部、宣传组、活动部、外联部、社区部，以及每条的 opening、description、mission、result。
- 移到作品和社区之后，先建立参与动机，再让访客选方向。
- 桌面使用五个具名标签按钮 + 一块开放式详情区，不再强制滚完五段。默认展示项目部，点击或键盘切换 200–280ms 淡入。详情强调“你的第一件事”和“你会留下的成果”。
- 正确实现 tablist、tab、tabpanel、aria-selected、aria-controls、方向键与 Home/End；焦点不因切换漂移。
- 移动端使用五个具名 disclosure/原生 details，默认展开第一项，可同时展开多个；不能只显示 01–05 隐藏部门名。
- 源码中的部门配置改用稳定 id/slug 匹配；新增或排序后的部门不能继承其他部门的第一任务。

### 06 FirstMonth：30 天，从旁观到参与。

- 保留现有 DAY 01 / WEEK 01 / WEEK 02 / DAY 30 四阶段。
- 桌面用连续时间轴，不用四张独立卡；移动端为纵向列表。连接线随阅读推进，但四个阶段从一开始就有文字。
- 合并原 gains：将“完成事情的能力、看得见的作品、一起走的人、更大的视野”分别放进四阶段的成果位置，或在时间轴下方做紧凑四列摘要，不删除其说明。
- 项目方向可保留第一次 commit；其他方向改成“完成第一次贡献”，并配内容、活动或社区任务，避免把非开发成员排除在叙事之外。
- 带教、时间承诺和任务安排须与实际运营政策一致，未确认时标明推荐成长路径，不承诺固定结果。

### 07 Future：把经验，留给下一个出发的人。

- 约半屏的极简过渡，承接 DAY 30 的复盘分享。
- 将现有“开放协作、真实项目、经验分享”凝练为未来方向；不虚构新项目、合作承诺或发布日期。
- 视觉以大字号、留白和一张真实公共成果缩略图为主，无新一套粒子/3D 场景。
- 过渡句：“下一段开源故事，等你来写。”

### 08 Join：带上好奇心，开始第一步。

- 保留现有四步报名流程：在线报名 → 开放交流 → 方向匹配 → 正式出发。压缩成一块清晰的流程说明，不占满屏。
- 保留四项 FAQ 的完整答案；原生 details，关闭与展开均有明确焦点样式。时间要求、零基础政策、跨方向参与、带教承诺须核验。
- 最终 CTA 回应首屏：“下一件作品，和你一起。”保留“下一段开源故事，等你来写”作为副标题或收束句。
- 主按钮统一为“查看招新与报名”，仍到既有 `/apply`，避免在不清楚开放状态时一律宣称“立即加入”。
- 已开放时显示真实招新批次、截止时间和报名入口；未开放时明确说明并给“浏览开放活动”至 `/activities`，不显示虚假倒计时。
- 结尾约 60–75svh，内容较多时自然长高。页脚保留品牌、官网返回入口及现有版权信息。

## 4. 视觉系统

| 项目 | 规格 |
| --- | --- |
| 核心材质 | 石墨、纸白、真实摄影、产品原色；玻璃仅用于少量悬浮导航 |
| 背景 | `#111214` 深色主场景，`#F5F5F2` 浅色阅读场景；根据现有主题语义 token 实现，不覆盖全站 |
| 文字 | 深底正文 `#F5F5F7` / 次级 `#B8BBC1`；浅底正文 `#17191D` / 次级 `#5D626B`；最终以对比度实测为准 |
| 强调色 | 从现有品牌蓝青中提取一个 token，经对比度验证后用于链接、进度和关键词；不要整页发光 |
| 字体 | 中文沿用 PingFang SC / Noto Sans SC；英文用项目已有 Space Grotesk，数字用 tabular-nums；Orbitron 不作长项目名称与正文默认字体 |
| 字号 | 桌面 Hero 88–112px，章节 48–64px，正文 18px；移动 Hero 44–52px，章节 32–38px，正文 16px；辅助文字 13–14px |
| 字重 | 中文 Hero 900、章节 800、项目标题 700，正文 400；使用实际可用字重，避免伪粗影响排版 |
| 排版 | 中文标题略松字距，英文标题约 -0.02em；正文不加宽字距。控制中文正文行长约 24–36 字 |
| 布局 | 沿用 1180px 主内容宽度，可给作品媒体单独 1320px 上限；桌面 12 栏、24px gutter，移动 20px 左右留白 |
| 间距 | 常规章节 80–120px，移动 56–72px；只有 Hero、作品和 Ending 有主场景高度，不统一 min-height:100svh |
| 圆角 | 图片/展台 20px，次要容器 12px，按钮胶囊；正文列表与时间线不额外套卡 |
| 明暗节奏 | 开场有色真实影像 → 安静阅读 → 深色作品 → 有温度的社区影像 → 清晰参与工具 → 深色收束；深色主题保持同样层次但不强制闪成白屏 |

## 5. 动效与交互规格

| 场景 | 实现 | 边界与降级 |
| --- | --- | --- |
| Hero | 一次性影像入场，滚动轻微缩放 | 文字初始可见；触屏不追随鼠标；减少动态效果时静态 |
| 协作故事 | CSS sticky 影像 + 三段自然文流；当前段驱动画面与关键词 | 不同时隐藏整段内容；移动无 sticky，不 snap |
| 项目展台 | CSS sticky 媒体 + ScrollTrigger/IntersectionObserver 更新 activeProjectId；媒体交叉淡入 250–350ms | 每个项目正文始终在文档流，链接可键盘访问；非当前媒体无可聚焦控件 |
| 常规段落 | 一次性 y:16–24px，450–600ms，power2.out | 不对每个标题都执行旋转缩放；动画加载失败全部可读 |
| 路线选择 | 200–280ms 淡入/轻移，显式点击 | 不自动轮换；可键盘切换；移动 details |
| 按钮与链接 | 160–220ms 色彩/边线变化；箭头移动约 3px | 不移动实际点击目标；focus-visible 对等；不做主 CTA 磁吸 |
| 项目 hover | 图片 scale ≤1.015；可选媒体层 tilt ≤2° | 仅 fine pointer，不能成为读取信息的唯一方式 |
| 页面定位 | 顶部章节导航、当前章节状态、可选 2px 滚动进度 | 恢复原生滚动条；所有锚点支持直接访问及浏览器后退 |

不要新增 Three.js、全屏粒子、自定义光标、强制横向滚动或第二个平滑滚动控制器。现有 Vue 3 + GSAP + ScrollTrigger 足够。

## 6. 开发拆分与数据约束

建议 `About.vue` 只负责页面编排，将视图拆为 BrandHero、OriginStory、ProjectShowcase、EvidenceCommunity、ParticipationPaths、FirstMonth、FutureStatement、JoinSection；命名均为建议的新组件，不代表已创建。

数据与生命周期放入 `useAboutContent`，动效放入 `useAboutMotion` 或各组件作用域，样式用局部 `--about-*` token 映射现有全站变量。不要继续在 2530 行单文件中叠加末尾覆盖规则。

项目展示模型建议：`id, slug, name, summary, audience, problem, outcome, status, cover, gallery[], detailUrl, repositoryUrl?, demoUrl?, contributors[], evidence[]`。新增字段需要先核查现有接口，不能假定已经存在。精选顺序由稳定 id 配置决定，不以接口前三项决定，不将不同来源的项目混搭。

- 接口成功：整条数据正规化后展示；缺失字段不编造。
- 接口空：明确暂无公开案例，保留应用目录入口。
- 接口失败：独立错误/重试，不冒充真实项目填默认卡。
- 图片失败：保留项目标题、说明及真实链接，显示轻量图片不可用状态；不出现破图图标。
- 荣誉失败与没有荣誉要区分，不统一写“荣誉仍在继续”。
- 统计仅来自同一核验口径，不把精选成员数当作全社人数。
- 成员引用、项目截图和人物影像确认公开授权，并移除手机号、邮箱、成绩、面试等敏感数据。

生命周期要求：组件挂载后创建 scoped GSAP context/matchMedia；卸载时 revert 并清理监听器、定时器、observer。异步响应设置卸载保护。核心内容与 Hero 不等待全部接口才初始化；避免用户已经滚动后再执行 resetPageScroll。图片解码、字体与异步布局稳定后批量 refresh，不逐帧 refresh。浏览器返回和带 hash 进入不能无条件重置顶部。

资料依据：[GSAP matchMedia](https://gsap.com/docs/v3/GSAP/gsap.matchMedia()/) 支持按断点与减少动态效果条件创建和回收动画。

## 7. 性能与可访问性验收

以下是验收目标，不是本次测量结果。

- 核心 Web 指标目标：真实用户第 75 百分位 LCP ≤2.5s、INP ≤200ms、CLS ≤0.1；实验室测试补充慢网与中低端设备，不用单次 Lighthouse 分数冒充线上结论。依据：[Web Vitals](https://web.dev/articles/vitals)。
- Hero 图片目标：桌面约 250–400KB，移动约 120–200KB，按画质复核；提供 AVIF/WebP、srcset/sizes。仅首图高优先级，影集按需加载。截图指定宽高/比例。
- 字体优先复用已有资源，不为了三个英文标签加载全套新字体；中文大字重按需子集化。
- 只对实际动画图层短期设置 will-change；离屏与 document.hidden 暂停动态背景；原生滚动，不阻塞触摸手势。
- 动态偏好在运行时变化也能立即生效；无动态模式全部正文可见、项目逐项阅读、无 pin/snap/视差/计数动画。交互动效可关闭的依据：[W3C Animation from Interactions](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html)。
- 所有主要点击目标至少 44×44px；键盘 focus 清晰；一个 h1，标题顺序合理；正文对比度至少 4.5:1，不用颜色单独表达状态。
- 首屏、项目、报名不依赖 hover；图片与装饰区分 alt；读屏不逐字播报滚动变化；保留原生 FAQ 和加入页面。
- 375/390/768/1068/1440px、短高横屏、200% 缩放、键盘、触摸、减少动态效果、图片/接口失败、返回恢复、hash 直达都列入验收。
- 对比首页与现有管理页，确认 `/about` 的局部 token、overflow 与 scroll 行为不会泄漏至其他路由。

## 8. 实施优先级

1. P0：修复项目/部门 index 混搭、恢复滚动条和锚点/返回行为、明确媒体与引用的真实性、移除移动 pin/snap。
2. P1：完成静态新叙事、Hero、真实截图展台、路线选择和统一 CTA；保留所有原信息的入口。
3. P2：添加三处必要的动效、微交互和媒体优化。
4. P3：全断点、可访问性、失败状态与性能验收。未达标时优先移除装饰动效，不删内容。

最终标准：用户不需要看完五条路线，就能理解社团并看到作品；用户不需要等待动画，就能阅读与操作；看完作品后能明确选择参与方向，并知道加入后第一件事是什么。
