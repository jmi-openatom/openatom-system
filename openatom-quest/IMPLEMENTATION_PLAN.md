# OpenAtom Quest MVP 实施计划

> 基线：`PRD.md` V1.0；本计划只实现 PRD 22.1 的第一阶段，22.2 与 22.3 保留扩展点。

## 1. 已确认的产品与技术决策

- 作为 `openatom-system/openatom-quest` 下的独立全栈子项目交付，不修改主站现有业务。
- 前端采用 Vue 3、TypeScript、Vite、Vue Router、Pinia、Element Plus、Axios、ECharts。
- 后端采用 Java 21、Spring Boot 3.3、MyBatis Plus、Flyway、MySQL 8、Redis。
- 身份源仅使用现有 OpenAtom OAuth 2.0 / OIDC，稳定关联键为 `sub`。
- OAuth 采用 Authorization Code + PKCE；上游 Token 只保存在服务端。认证中心自动注册无 Secret 的公开客户端，如后续启用 Secret 则仅通过服务端环境变量注入。
- Quest 自己维护成员状态、角色、权限和数据范围；OAuth 返回的主站角色不自动转成 Quest 管理权限。
- UI 参考主站：复用中性色、排版、4px 栅格、圆角、轻边框、毛玻璃导航、亮暗主题和响应式规则。
- 项目广场、徽章、团队任务、排行榜、外部代码托管同步不进入第一阶段。

## 2. 交付顺序

### 阶段 A：工程与安全基座

- 前后端工程、Docker Compose、环境变量模板、健康检查。
- Quest 本地会话、OAuth 登录/回调/刷新/退出、`state`、`nonce`、PKCE。
- 成员、OAuth 身份、角色、权限、审计日志基础表。
- 未登录、未完善资料、未完成引导、已禁用用户的统一路由与接口守卫。

验收：相同 `sub` 幂等登录；认证失败不建成员；禁用用户无法进入；退出后会话失效。

### 阶段 B：成员资料与新人引导

- 首次资料完善、技术方向、技能自评、行为准则确认。
- 7 步新人引导及可恢复进度；工作台持续显示下一步。
- 管理员维护技术方向。

验收：首次登录路径、草稿保存、完成后跳转工作台、引导进度恢复。

### 阶段 C：成长路线与任务中心

- 路线、阶段、任务、前置任务、发布/下架/归档。
- 主动领取、管理员分配、人数/截止/前置条件校验。
- 新成员工作台、路线页、任务中心与任务详情。

验收：管理员发布路线和任务；成员只能领取满足条件的任务；历史对象不能物理删除。

### 阶段 D：提交、审核与积分闭环

- 成果草稿、附件元数据、仓库/PR/演示链接、AI 使用说明。
- 每次提交生成不可覆盖版本；导师审核、退回、重提、转交、申诉。
- 基础评分、幂等积分流水、等级更新、路线进度更新。

验收：领取→提交→退回→重提→通过全链路可追溯，积分只发一次。

### 阶段 E：通知、管理与统计

- 站内通知与已读状态。
- 导师工作台、管理员后台、成员/角色/任务/路线管理。
- 登录、完成率、审核时长、路线完成率等基础统计。
- 权限、数据范围和关键业务操作日志。

验收：不同角色只能看到授权数据；关键动作有历史；统计口径可复算。

### 阶段 F：整体验收

- 后端单元/集成测试、前端类型检查与构建。
- 核心流程端到端测试、移动端布局与亮暗主题检查。
- 对照 PRD 25 节逐条形成验收清单。

## 3. 环境配置边界

以下信息不阻塞本地开发，先通过环境变量占位；正式联调或部署前必须提供：

- OAuth 客户端如需升级为机密客户端时使用的服务端 `client_secret`；
- 正式 MySQL、Redis、对象存储和 HTTPS 配置。

正式域名：`https://quest.jmi-openatom.cn`；精确回调地址：`https://quest.jmi-openatom.cn/api/auth/callback`。

默认上游 Issuer：`https://oauth.jmi-openatom.cn/api/v1`；Client ID：`openatom-quest`。

## 4. UI 对齐清单

- 复用主站 `Space Grotesk + Noto Sans SC` 字体组合。
- 复用 `#1d1d1f` 主色、`#f5f5f7` 页面背景及主站状态色。
- 前台使用毛玻璃顶栏；导师/管理员使用可折叠侧栏和毛玻璃工具栏。
- 页面统一为“标题与操作 → 筛选/状态 → 内容卡片”。
- 状态色只表达状态，不作为装饰；所有颜色通过语义 Token 使用。
- 支持暗色模式、键盘焦点、减少动态效果和 767px 以下移动端布局。
